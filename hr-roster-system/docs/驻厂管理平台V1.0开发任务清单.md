## 1. 现有项目改造原则

- 后端继续使用 `src/app.js`、`src/routes/`、`src/controllers/`、`src/services/`。

- MySQL 结构继续维护在 `sql/schema.mysql.sql`，建议同时新增可回滚迁移脚本目录。

## 2. 数据库任务

### DB-001 员工生命周期字段

- 为员工表增加生命周期、到岗、保险、合同、资料、风险和招聘来源字段。
- 增加项目、状态和来源统计索引。
- 保留现有员工状态字段用于灰度兼容。

### DB-002 任职历史

- 新建 `employee_assignments`。
- 为现有在职员工补充当前有效任职记录。
- 调岗时结束旧任职并新增任职，不再覆盖历史。

### DB-003 招聘来源

- 新建 `recruiters`。
- 新建 `recruitment_suppliers`。
- 新建 `recruitment_batches`。
- 新建 `recruitment_source_changes`。

### DB-004 统一待办

- 新建 `work_tasks`。
- 对来源业务、任务类型和有效状态建立唯一约束，防止重复待办。

### DB-005 员工异动

- 新建 `employee_changes`。
- 支持入职、转岗、离职业务类型。
- 保存原项目、目标项目、生效日期、原因、状态和复核人。

## 3. 后端任务

### BE-001 角色迁移

- 删除界面中的项目主管角色。
- 将历史项目主管账号映射为驻厂人员。
- 保留原授权项目和未完成待办。
- 增加跨项目接收、离职交接和投保办理权限。

### BE-002 员工状态机

- 新增生命周期常量和状态流转服务。
- 禁止非法状态跳转。
- 所有状态变化写入审计日志。

### BE-003 员工预检查

```http
POST /api/v1/employees/precheck
```

检查身份证、黑名单、有效任职、年龄、项目岗位和证件要求。

### BE-004 新增员工

```http
POST /api/v1/employees
```

使用事务完成员工、任职、招聘来源、附件引用和待办创建。支持幂等键。

### BE-005 到岗与未到岗

```http
POST /api/v1/employees/:id/confirm-arrival
POST /api/v1/employees/:id/cancel-onboarding
```

到岗后锁定来源，激活任职，生成投保、合同和资料任务。

### BE-006 招聘人和供应商

```http
GET/POST/PUT /api/v1/recruiters
GET/POST/PUT /api/v1/suppliers
GET/POST/PUT /api/v1/recruitment-batches
```

供应商合同过期或停用时禁止新增关联。

### BE-007 转岗

```http
POST /api/v1/employees/:id/transfers
PUT /api/v1/transfers/:id/accept
PUT /api/v1/transfers/:id/reject
PUT /api/v1/transfers/:id/cancel
```

实现项目内、跨项目、跨客户三种流程。

### BE-008 离职

```http
POST /api/v1/employees/:id/offboarding
PUT /api/v1/offboarding/:id/handover
PUT /api/v1/offboarding/:id/confirm
PUT /api/v1/offboarding/:id/cancel
```

生成交接、工资、退保和合同终止任务。

### BE-009 待办中心

- 创建、查询、开始处理、转派、完成和关闭。
- 高风险任务只能通过业务动作完成。
- 没有责任人的任务进入管理员异常队列。

### BE-010 定时任务

- 到岗未投保检查。
- 待办超时升级。
- 保险和证件到期检查。
- 离职未退保检查。
- 供应商合同到期检查。
