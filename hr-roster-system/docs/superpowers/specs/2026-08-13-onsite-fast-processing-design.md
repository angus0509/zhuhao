# 驻厂快速办理流程设计

## 1. 目标

将微信小程序驻厂端收敛为一条最短人员流转路径：

```text
录入新员工 → 待到岗 → 在职员工 → 已离职
                    └→ 未入职 → 人才库
```

驻厂人员无需进入处理队列、合规待办、合同登记或雇主险确认页面。所有核心操作直接在人员状态列表完成。

## 2. 本次范围

### 2.1 本次实现

- 简化微信小程序工作台。
- 简化微信小程序驻厂人员状态和操作。
- 新增员工默认进入待到岗。
- 驻厂人员可查看、编辑授权范围内员工的完整业务资料。
- 待到岗支持确认入职和未入职。
- 在职支持一键办理离职。
- 未入职和离职人员同步人才库。
- 保持网页端、小程序端和 REST API 使用同一员工状态事实源。
- 保持企业、客户、项目和驻厂专员数据隔离。

### 2.2 本次不删除

- 不删除劳动合同历史记录。
- 不删除雇主险历史记录。
- 不删除历史工作待办和操作日志。
- 不删除网页端已有合同、雇主险和风险管理能力。
- 不修改工资、预支、招聘渠道等其他业务模块。

## 3. 用户角色和权限

### 3.1 企业管理员

- 查看和管理本企业全部员工。
- 为驻厂专员分配客户和项目范围。
- 查看历史合同、雇主险、离职和人才库信息。

### 3.2 HR 主管

- 在授权组织、客户和项目范围内管理员工。
- 可录入、编辑、确认入职、标记未入职和办理离职。

### 3.3 驻厂专员

- 只能查看自己授权客户和项目下的员工。
- 可录入新员工。
- 可查看员工全部业务字段；身份证号、银行卡号等敏感字段仍按既有权限与脱敏规则输出。
- 可编辑自己授权范围内的员工。
- 可确认入职、标记未入职和一键离职。

### 3.4 薪资专员

- 不新增驻厂生命周期写入权限。
- 继续按原有权限处理工资和预支。

## 4. 状态模型

| employee_status | 业务含义 | 小程序驻厂端展示 |
|---:|---|---|
| 1 | 待到岗 | 待到岗 |
| 2 | 在职 | 在职员工 |
| 3 | 已离职 | 已离职 |
| 5 | 未入职 | 不在驻厂状态栏展示，进入人才库 |
| 6 | 历史面试状态 | 兼容存量数据，按待到岗展示和处理 |

新录入员工固定使用：

```text
employee_status=1
lifecycle_status='PENDING_ARRIVAL'
arrival_status='PENDING'
```

不再从小程序新增入口产生 `employee_status=6` 的面试记录。

## 5. 小程序页面结构

### 5.1 工作台

工作台驻厂核心区域只保留四个入口：

1. 录入新员工
2. 待到岗
3. 在职员工
4. 已离职

删除或隐藏以下驻厂入口和模块：

- 驻厂待处理统计卡。
- 合规待办统计卡。
- 驻厂处理队列。
- 今日待办中的合同、雇主险和驻厂生命周期处理入口。
- 合同与雇主险一键确认入口。

工作台可保留预支、工资、招聘渠道等与驻厂生命周期无冲突的通用快捷功能。

### 5.2 驻厂人员管理

状态栏固定显示：

- 全部人员
- 待到岗
- 在职员工
- 已离职

不显示：

- 面试
- 未入职
- 离职办理
- 雇主险筛选
- 合规状态筛选

客户切换继续保留。切换客户后，状态数量和员工列表必须同步刷新，只展示当前账号授权范围内的数据。

### 5.3 员工卡片操作

| 状态 | 操作 |
|---|---|
| 待到岗 | 查看、编辑、确认入职、未入职 |
| 在职员工 | 查看、编辑、一键办理离职 |
| 已离职 | 查看档案 |

员工卡不再显示：

- 一键确认合同和雇主险。
- 单独登记合同。
- 单独办理雇主险。
- 转为待到岗。
- 未通过/不做。

### 5.4 员工详情与编辑

驻厂专员在授权范围内可查看和编辑：

- 姓名、性别、手机号。
- 身份证号码、身份证地址、现住地址。
- 银行卡号、开户行。
- 客户单位、项目、岗位。
- 用工模式、费用模式、工资类型。
- 招聘渠道、招聘来源备注。
- 入职日期、离职信息。
- 其他现有员工档案字段。

保存编辑时继续执行企业 ID、客户、项目和员工数据范围校验。

## 6. 核心业务流程

### 6.1 录入新员工

1. 驻厂人员点击“录入新员工”。
2. 填写员工基础信息；用工和计费信息、招聘来源与备注继续允许后补。
3. 保存为待到岗状态。
4. 员工立即进入当前客户的“待到岗”列表。
5. 不创建合同、雇主险或合并合规待办。
6. 写入新增员工操作日志。

### 6.2 确认入职

1. 驻厂人员在待到岗列表点击“确认入职”。
2. 系统校验身份证、手机号、客户、项目、岗位、用工模式、工资类型和入职日期等入职必填字段。
3. 更新：
   - `employee_status=2`
   - `lifecycle_status='ACTIVE'`
   - `arrival_status='CONFIRMED'`
4. 关闭该员工已有的到岗待办。
5. 不创建合同、雇主险或 `ONBOARDING_COMPLIANCE` 待办。
6. 员工立即进入“在职员工”。
7. 写入确认入职操作日志。

### 6.3 未入职

1. 驻厂人员在待到岗列表点击“未入职”。
2. 填写或确认未入职原因，原因允许简短文本。
3. 更新：
   - `employee_status=5`
   - `lifecycle_status='NOT_JOINED'`
   - `arrival_status='NO_SHOW'`
4. 关闭该员工开放的到岗和历史合规待办。
5. 以 `UNJOINED` 来源同步人才库。
6. 员工从驻厂状态列表退出。
7. 写入未入职操作日志。

### 6.4 一键办理离职

1. 驻厂人员在在职列表点击“一键办理离职”。
2. 填写离职日期、离职类型、离职原因和实际适用的交接项。
3. 不要求合同确认或雇主险减保确认。
4. 同一事务执行：
   - 创建并办结离职记录。
   - 更新 `employee_status=3`。
   - 更新 `lifecycle_status='LEFT'`。
   - 关闭当前任职记录并保留最近客户、项目和岗位归属。
   - 关闭员工开放的工作待办和风险提醒。
   - 停用关联员工账号并递增 `token_version`。
   - 以 `RESIGNED` 来源同步人才库。
   - 写入离职操作日志。
5. 员工立即进入“已离职”。

## 7. REST API

### 7.1 新增员工

```text
POST /api/employees
权限：employee:create
```

小程序新增请求固定提交：

```json
{
  "employeeStatus": 1
}
```

后端仍兼容网页端和历史接口提交的其他合法状态，但小程序不再提供状态选择。

### 7.2 确认入职

```text
POST /api/employees/:id/onboard
权限：employee:update
```

成功后不生成合规待办。

### 7.3 标记未入职

```text
PUT /api/employees/:id/arrival-result
权限：employee:update
```

请求：

```json
{
  "result": "UNJOINED",
  "remark": "员工未按约定到岗"
}
```

### 7.4 一键离职

```text
POST /api/employees/:id/resign
权限：employee:resign
```

取消小程序端对“雇主险已减保”字段的强制校验。后端保留历史字段兼容，但不再把该字段作为离职办结条件。

### 7.5 员工详情与编辑

```text
GET /api/employees/:id
PUT /api/employees/:id
权限：employee:view / employee:update
```

必须同时校验：

- `company_id`。
- 用户客户/项目数据范围。
- 离职员工最近一次任职归属。
- 敏感字段查看权限和脱敏规则。

## 8. 数据与兼容策略

- 不删除 `hr_labor_contract`、`hr_social_security`、`hr_work_task` 或风险历史数据。
- 新确认入职不再创建 `ONBOARDING_COMPLIANCE`、`CONTRACT` 或 `INSURANCE` 待办。
- 迁移关闭现有开放的驻厂合同、雇主险和合并合规待办，保留历史状态和完成时间。
- 小程序不再导航到合同、雇主险或合并合规页面；页面文件可保留用于历史版本兼容，但不进入新流程。
- 网页端仍可独立维护合同和雇主险，不影响驻厂快速办理。
- 历史 `employee_status=6` 面试人员在小程序驻厂端并入待到岗展示，操作与待到岗一致。

## 9. 权限与风控

- 所有员工读取和写入必须由后端校验数据范围，不能只依赖小程序隐藏按钮。
- 驻厂专员只能操作授权项目员工。
- 已离职员工账号立即失效。
- 新增、编辑、确认入职、未入职和离职全部写审计日志。
- 身份证、银行卡号、手机号继续执行既有加密存储和按权限脱敏。
- 不在日志中记录完整身份证、银行卡、密码或 Token。

## 10. 错误处理

- 重复确认入职：返回“员工已在职，无需重复确认”，小程序刷新列表。
- 已非待到岗状态执行未入职：返回真实状态并刷新列表。
- 非授权客户/项目员工：返回 403，不泄露员工资料。
- 离职事务任一步骤失败：全部回滚，员工保持在职。
- 编辑保存失败：保留表单内容并显示具体错误，不重复提交。

## 11. 验收标准

1. 小程序工作台驻厂区域只显示录入新员工、待到岗、在职员工、已离职。
2. 小程序不显示驻厂待处理、合规待办和驻厂处理队列。
3. 小程序驻厂状态栏只显示全部人员、待到岗、在职员工、已离职。
4. 新增员工默认进入待到岗，不出现面试状态选择。
5. 待到岗确认入职后立即进入在职员工，且不产生任何合同或雇主险待办。
6. 待到岗标记未入职后进入人才库并退出驻厂列表。
7. 在职员工一键离职后立即进入已离职并同步人才库。
8. 小程序驻厂入口不再出现合同、雇主险或合并合规按钮。
9. 驻厂专员可查看、编辑授权范围内员工完整业务资料。
10. 驻厂专员无法查看或修改非授权客户和项目员工。
11. 网页端、小程序端和 API 的待到岗、在职、已离职数量一致。
12. lint、全量测试、依赖安全检查和发布前检查全部通过。
