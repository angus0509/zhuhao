# 驻厂员工生命周期简化设计

## 1. 目标

将驻厂人员管理统一为一条可直接操作的主流程：

```text
面试 → 待到岗 → 正常在职 → 已离职
  └→ 未通过/不做 → 人才库
       待到岗 └→ 未入职 → 人才库
```

合同与雇主险合并办理；离职、雇主险减保、账号失效、人才库回流在一个事务内完成。

## 2. 用户角色与权限

### 企业管理员

- 查看和处理全公司员工生命周期。
- 配置驻厂专员、HR主管、薪资专员的角色权限和项目范围。

### HR主管

- 在授权部门和项目范围内处理面试、到岗、入职、合规和离职。

### 驻厂专员

- 只能查看自己负责客户和项目的员工。
- 可将面试人员转为待到岗或未通过。
- 可将待到岗人员确认入职或标记未入职。
- 可一键确认合同和雇主险。
- 可一键办理离职。

### 薪资专员

- 不获得员工生命周期写入权限，仅按已有薪资权限处理工资和预支。

## 3. 状态模型

数据库保留历史状态值，避免破坏已有数据：

| employee_status | 业务含义 | 驻厂页面展示 |
|---:|---|---|
| 6 | 面试 | 面试 |
| 1 | 待到岗 | 待到岗 |
| 2 | 在职 | 正常在职 |
| 5 | 未入职/面试未通过 | 不在驻厂状态栏展示，进入人才库 |
| 3 | 已离职 | 已离职 |

`lifecycle_status='OFFBOARDING'` 仅兼容历史未办结记录。新的一键离职流程不再停留在离职办理中。

## 4. 核心业务流程

### 4.1 新增面试人员

1. 新增员工默认录入状态为“面试”。
2. 保存后出现在驻厂管理对应客户的“面试”列表。
3. 面试人员详情只显示两个主操作：
   - 待到岗
   - 未通过/不做

### 4.2 面试转待到岗

1. 校验员工仍为面试状态。
2. 更新：
   - `employee_status=1`
   - `lifecycle_status='PENDING_ARRIVAL'`
   - `arrival_status='PENDING'`
3. 创建或重新打开唯一的 `ARRIVAL` 待办。
4. 员工从“面试”退出并进入“待到岗”。

### 4.3 面试未通过/不做

1. 校验员工仍为面试状态。
2. 更新：
   - `employee_status=5`
   - `lifecycle_status='NOT_JOINED'`
   - `arrival_status='NO_SHOW'`
3. 关闭员工所有未完成的到岗、合同、雇主险待办和风险提醒。
4. 以 `INTERVIEW_REJECTED` 来源同步人才库。
5. 员工从驻厂管理状态列表退出。

### 4.4 待到岗确认入职

1. 校验员工为待到岗状态并补齐身份证、手机号、客户、项目、岗位、用工模式、工资类型和入职日期。
2. 更新：
   - `employee_status=2`
   - `lifecycle_status='ONBOARDING'`
   - `arrival_status='CONFIRMED'`
3. 关闭 `ARRIVAL` 待办。
4. 创建一个员工级 `ONBOARDING_COMPLIANCE` 合并待办。
5. 员工进入“正常在职”。

### 4.5 待到岗未入职

1. 校验员工仍为待到岗状态。
2. 更新为 `employee_status=5`、`lifecycle_status='NOT_JOINED'`、`arrival_status='NO_SHOW'`。
3. 关闭该员工未完成的生命周期和合规待办。
4. 以 `UNJOINED` 来源同步人才库。
5. 员工从驻厂管理状态列表退出。

### 4.6 一键确认合同和雇主险

前端页面仅保留以下字段：

- 合同是否已签，固定本操作为“已签”。
- 合同签订日期，默认当天，可调整。
- 雇主险是否已增保，固定本操作为“已增保”。
- 雇主险生效日期，默认当天，可调整。
- 备注，选填。

同一数据库事务执行：

1. 写入或更新已签劳动合同记录。
2. 写入或更新雇主险保障中记录。
3. 更新员工 `contract_status='SIGNED'`、`insurance_status='ACTIVE'`、`lifecycle_status='ACTIVE'`。
4. 关闭 `CONTRACT`、`INSURANCE` 和 `ONBOARDING_COMPLIANCE` 待办。
5. 关闭合同未签和雇主险未增保风险提醒。
6. 写入操作日志。

历史单独合同和雇主险接口继续保留，供已有页面兼容，但驻厂和合规主入口统一使用合并接口。

### 4.7 一键办理离职

页面字段：

- 离职日期
- 离职类型
- 离职原因
- 适用的交接清单，可按实际情况勾选
- 雇主险已减保确认；当前保障中时必须勾选

同一数据库事务执行：

1. 创建离职记录并立即办结。
2. 当前雇主险保障中时登记减保。
3. 更新员工为 `employee_status=3`、`lifecycle_status='LEFT'`、`insurance_status='TERMINATED'`。
4. 关闭当前任职记录，但保留最近一次客户、项目和岗位供已离职列表查询。
5. 关闭员工所有未完成工作待办和开放风险。
6. 停用员工关联账号并递增 `token_version`。
7. 以 `RESIGNED` 来源同步人才库。
8. 写入离职和减保操作日志。
9. 员工立即进入“已离职”，同时出现在人才库。

## 5. 页面结构

### 小程序驻厂管理

状态栏只显示：

- 全部
- 面试
- 待到岗
- 正常在职
- 已离职

不显示：

- 未入职
- 离职办理
- 雇主险独立筛选入口

员工卡操作：

| 当前状态 | 操作 |
|---|---|
| 面试 | 待到岗、未通过/不做 |
| 待到岗 | 确认入职、未入职 |
| 正常在职 | 编辑、一键确认合同和雇主险、一键办理离职 |
| 已离职 | 查看档案 |

### 小程序工作台和合规待办

- 合同待办和雇主险待办按员工去重为一个“一键确认合同和雇主险”。
- 同一员工只出现一条合规处理事项。
- 办理成功后从处理队列立即消失。

### 网页端

- 风险中心的合同和雇主险事项按员工合并显示。
- 员工详情增加“一键确认合同和雇主险”。
- 一键离职复用同一后端事务。
- 网页花名册仍只显示正常在职员工；已离职人员从人才库和员工档案查询。

## 6. REST 接口

### 面试结果

```text
PUT /api/employees/:id/interview-result
权限：employee:update
```

请求：

```json
{
  "result": "PENDING_ARRIVAL",
  "remark": "周一到岗"
}
```

`result` 仅允许：`PENDING_ARRIVAL`、`REJECTED`。

### 待到岗结果

继续使用已有入职接口确认入职：

```text
POST /api/employees/:id/onboard
```

新增未入职接口：

```text
PUT /api/employees/:id/arrival-result
权限：employee:update
```

请求：

```json
{
  "result": "UNJOINED",
  "remark": "员工放弃到岗"
}
```

### 合同和雇主险合并办理

```text
POST /api/employees/:id/onboarding-compliance/confirm
权限：同时要求 contract:manage 和 social:manage
```

请求：

```json
{
  "contractDate": "2026-08-13",
  "insuranceStartDate": "2026-08-13",
  "remark": "现场已核验"
}
```

### 一键离职

继续使用：

```text
POST /api/employees/:id/resign
权限：employee:resign
```

接口调整为一次请求直接办结，不再产生新流程中的离职办理中状态。

## 7. 数据库与兼容策略

- 不删除现有字段、状态或历史记录。
- `employee_status=5` 继续用于未入职和面试未通过的人才库快照。
- 保留旧 `CONTRACT`、`INSURANCE`、`OFFBOARD` 和 `INSURANCE_TERMINATION` 待办类型，用于历史数据识别。
- 新入职流程使用 `ONBOARDING_COMPLIANCE` 合并待办。
- 发布迁移将同一在职员工开放的合同、雇主险待办合并：保留一条合并待办并关闭旧开放待办。
- 历史 `OFFBOARDING` 人员不强制自动离职，由原流程继续处理；新流程不再创建新的离职中记录。

## 8. 权限与风控

- 所有接口必须校验企业 ID 和员工数据范围。
- 驻厂专员只能处理授权项目员工；离职后仍按最近一次项目判断查看权限。
- 合并合规接口必须同时具备合同和雇主险权限，不能只依赖前端隐藏按钮。
- 面试结果、未入职、合规确认和离职全部写操作日志。
- 身份证、银行卡、手机号继续脱敏；本次流程不增加敏感信息输出。
- 一键离职继续使关联员工账号立即失效。

## 9. 错误处理

- 状态不匹配返回明确提示，例如“该员工已不在面试状态，请刷新列表”。
- 重复点击已完成操作时返回当前真实状态，前端刷新员工和待办数据，不保留错误卡片。
- 合同写入成功但雇主险失败时整个事务回滚，不产生半完成状态。
- 离职任一步骤失败时整个事务回滚，员工保持原在职状态。

## 10. 测试与验收

必须增加并验证：

1. 面试转待到岗后只出现在待到岗。
2. 面试未通过进入人才库且不出现在驻厂状态列表。
3. 待到岗确认入职后进入正常在职并关闭到岗待办。
4. 待到岗未入职进入人才库。
5. 合同和雇主险合并办理成功后关闭全部合规待办和风险。
6. 合并办理任一步骤失败时事务回滚。
7. 一键离职后立即进入已离职和人才库，关联账号失效。
8. 驻厂专员无法处理非授权项目员工。
9. 网页端、小程序和 API 状态名称及数量一致。
10. lint、全量测试、依赖安全检查和发布校验全部通过。
