# 雇主险模块下线设计

## 1. 决策与目标

系统不再提供雇主险办理、查询、统计、提醒或导出能力。网页端、手机 Web、微信小程序和管理接口统一去除雇主险业务含义，避免继续影响员工、项目、风险和运营统计。

本次采用“功能彻底下线、历史数据保留”方案：

- 删除所有用户可见入口、字段、状态、提示、筛选、统计和导出项。
- 停止雇主险写入、计算、待办、风险、通知和权限授权。
- 保留数据库现有字段、历史记录、历史审计日志和旧迁移文件。
- 不执行 `DROP`、`DELETE`、`TRUNCATE`，不自动篡改历史雇主险状态。

本设计取代旧文档中仍要求办理、统计或导出雇主险的内容；员工到岗、在职、离职和工资流程不再依赖雇主险。

## 2. 范围

### 2.1 本次下线

- Web 花名册客户分组中的“雇主险缺口”。
- Web、手机 Web 和小程序员工详情中的雇主险状态与办理入口。
- 小程序雇主险页面及对应页面路由。
- 员工列表、详情和导出中的雇主险字段。
- Excel 的“雇主险信息”工作表。
- 驾驶舱、项目和运营统计中的雇主险人数、覆盖率、缺口率。
- 雇主险增保、减保、离职减保和合并合规接口。
- `social:manage` 中仅服务于雇主险的权限名称、默认角色授权和页面判断。
- 雇主险待办、风险扫描、风险重新打开、通知生成和消息文案。
- 与雇主险绑定的测试契约，改为验证系统不存在可操作入口和业务依赖。

### 2.2 明确保留

- `hr_social_security` 中现有雇主险历史字段和值。
- 历史操作日志、已关闭风险、已关闭待办和历史通知记录。
- 已执行的 SQL 迁移文件，作为数据库演进记录，不回改、不删除。
- 与社保本身有关且仍被其他业务使用的数据和能力；不得因名称相近误删。
- 通用附件能力；仅移除“雇主险材料”的业务文案和入口。

## 3. 客户端设计

### 3.1 Web 与手机 Web

- 花名册客户卡只保留在职人数和风险数，不显示雇主险缺口。
- 员工表格、详情、编辑、离职和快捷操作不出现雇主险。
- 驾驶舱、办公中心、项目卡和运营消息不出现雇主险指标或提示。
- CSV/XLSX 导出不包含雇主险状态列，不创建“雇主险信息”工作表。
- 历史通知若正文包含雇主险，继续在办公消息层过滤，不重新展示。

### 3.2 微信小程序

- 从 `app.json` 和可达导航中移除员工雇主险页面。
- 员工列表、详情、编辑、确认入职和离职页面不读取或展示雇主险。
- 客户驾驶舱不计算 `insuranceComplete`、`insuranceGapCount` 等字段。
- 旧版本小程序调用已下线接口时，服务端返回明确的“该功能已停用”，不得执行写入。

## 4. 服务端与接口

### 4.1 员工查询

- `GET /api/employees` 不返回雇主险状态、日期或缺口统计。
- 员工详情不返回承保机构、保单号、日期和保额。
- 花名册分页客户汇总只返回客户、员工数、在职数和风险数。
- 数据范围校验保持不变，不扩大企业、客户或项目可见范围。

### 4.2 写接口

以下历史能力统一停用，不再进入业务事务：

- 雇主险增保/减保。
- 合同和雇主险合并确认。
- 离职流程中的雇主险减保。

为了兼容已发布旧客户端，原路由暂不直接删除；统一返回 HTTP `410` 和固定业务提示，不读取或修改雇主险数据。待旧客户端自然淘汰后，再单独评估删除路由。

示例响应：

```json
{
  "code": 410,
  "message": "雇主险功能已停用"
}
```

### 4.3 统计、风险与通知

- 删除实时统计 SQL 中的雇主险字段和派生比率。
- 风险扫描不再查询或生成雇主险风险。
- 不重新打开任何历史雇主险风险或待办。
- 旧开放记录继续通过既有停用迁移关闭；不删除历史记录。
- 新增员工、确认入职、调岗和离职不再创建任何雇主险任务、风险或通知。

## 5. 权限策略

- 移除界面和默认角色中的雇主险权限展示。
- 当前代码核查确认 `social:manage` 仅用于雇主险接口和保险材料附件，因此通过幂等迁移将权限本身设为停用；`sys_role_permission` 历史关联保留。认证查询只读取 `sys_permission.status=1`，停用后旧角色不会再获得该权限。
- 停用 `social` 类型附件的新上传和管理入口，既有附件文件和数据库记录继续保留。
- 迁移执行前必须查询权限实际绑定和接口用途，禁止直接删除权限行。
- 旧账号 Token 不因本次调整主动失效；服务端路由停用保证旧权限也无法继续写入。

## 6. 数据库与迁移

新增一份幂等迁移，仅处理配置和开放事项：

1. 查询并停用仅属于雇主险的菜单或权限配置。
2. 保留对应角色权限关联作为历史记录；权限停用后关联不会进入有效权限集合。
3. 将仍开放的雇主险待办和风险标记为已关闭，注明“功能已停用”。
4. 不修改员工历史雇主险字段。
5. 不删除表、列、审计日志、通知和附件。

迁移必须满足：

- 禁止 `DELETE`、`DROP`、`TRUNCATE`。
- 更新条件限定企业业务类型和未完成状态。
- 可重复执行，第二次执行不产生额外变化。
- 生产执行前单独备份并单独确认数据库迁移。

## 7. 与花名册分页修复的关系

- 花名册继续使用服务端分页，默认每页 50 人。
- 客户汇总不再查询或返回 `insuranceGapCount`，减少一次无用统计计算。
- 分页、搜索、客户筛选、员工详情和全量导出保持原有数据范围。
- 工资条导入现有修改不在本次重构范围内，只做回归验证。

## 8. 测试与验收

### 8.1 自动化测试

- 1000+ 员工场景首屏只请求和渲染 50 人。
- Web、手机 Web、小程序源码和路由中不存在可达雇主险入口。
- 员工列表、详情、客户汇总、驾驶舱、导出响应不包含雇主险字段。
- 旧雇主险写接口返回 `410`，数据库无写入。
- 入职、在职、调岗、离职流程不依赖雇主险状态。
- 不生成或重新打开雇主险待办、风险和通知。
- 企业、客户、项目和角色数据隔离回归通过。
- CSV/XLSX 导出不含雇主险列或工作表。
- `npm run check`、`npm audit --audit-level=high`、`git diff --check` 全部通过。

### 8.2 生产验收

- 网页和小程序主要流程中搜索“雇主险”无业务入口。
- 在职员工、项目、考勤、工资条和人才库功能正常。
- 旧客户端请求下线接口只收到停用提示，不产生数据变更。
- 生产容器、数据库、只读 smoke 和最近日志正常。
- 数据库中历史雇主险记录仍存在且未被改写。

## 9. 发布边界

- 本地实现、测试、提交、推送、数据库迁移、Web/API 部署和小程序上传分别确认。
- 本设计确认不代表授权生产迁移、部署或小程序上传。
- 任何删除历史数据或数据库字段的后续需求必须重新设计并单独确认。
