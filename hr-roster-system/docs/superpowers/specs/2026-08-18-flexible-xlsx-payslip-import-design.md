# 任意 XLSX 工资条智能导入设计

日期：2026-08-18

## 1. 需求概述

工资条导入支持 CSV 和 XLSX，不要求项目使用系统固定模板。系统自动识别标题行、单层或双层表头、员工身份列和常见工资项目；未识别的工资列不得丢弃，必须按原表名称、原表顺序和原始金额保存并展示。

成功标准：

- 不同项目可以直接上传各自工资表，不必调整为统一列顺序。
- 姓名、工号、身份证号、手机号可单独或组合匹配员工。
- 常见工资字段自动匹配；无法确定的关键字段由薪资专员在预览页指定一次。
- 字段映射按企业和项目保存，同类表格再次上传时自动复用。
- 网页管理端预览内容、小程序员工工资条和上传原表保持一致。
- 现有工资批次、工资条签收、撤回、异议及审计功能保持不变。

## 2. 用户角色

| 角色 | 权限 |
| --- | --- |
| 企业管理员 | 查看全部授权项目工资批次，维护项目字段映射 |
| 薪资专员 | 在管理员授权项目内上传、映射、预览和创建工资批次 |
| HR 主管 | 按现有工资权限查看工资条发放结果 |
| 员工 | 仅查看、签字和签收本人已发布工资条 |

## 3. 功能模块

### 3.1 文件读取

- 支持 `.xlsx`、`.csv`，单文件最大 10 MB。
- XLSX 遍历全部工作表，选择第一个满足识别条件的明细表。
- 检查前 20 行，支持标题、制表日期、空行、单层表头和双层表头。
- 单批最多 500 名员工、100 列。
- 公式单元格不执行公式；要求上传前转换为固定数值。

### 3.2 字段自动识别

标准字段继续识别：

- 员工身份：姓名、工号、身份证号、手机号。
- 汇总金额：应发工资、实发工资。
- 收入项目：基本工资、岗位工资、绩效、补贴、计件、1.5 倍/2 倍/3 倍加班费。
- 扣款项目：个税、预支扣回、社保扣款、其他扣款。

未知列处理：

- 非空未知列全部保留，不再标记为“忽略”。
- 数值列自动建议为收入、扣款或展示项。
- 文本列默认作为展示项，可由薪资专员取消展示。
- 工号、身份证号、手机号等身份列不得进入工资条项目快照。

### 3.3 字段映射

仅在以下情况打开映射面板：

- 未识别到员工身份列。
- 未识别到实发工资列。
- 同一关键字段存在多个候选列。
- 已保存映射与本次表头不一致。

映射类型：`员工姓名`、`工号`、`身份证号`、`手机号`、`应发工资`、`实发工资`、`收入项目`、`扣款项目`、`展示项`、`不导入`。

创建工资批次前至少满足：

- 存在一种员工身份匹配方式。
- 实发工资列唯一且有效。
- 每行实发工资为非负数。
- 员工属于所选企业、客户项目且当前在职。

### 3.4 工资项目快照

每名员工保存本次导入的动态工资项目，示例：

```json
[
  { "label": "底薪", "value": 4500, "category": "income", "sortOrder": 1 },
  { "label": "夜班奖", "value": 380, "category": "income", "sortOrder": 2 },
  { "label": "住宿扣款", "value": 150, "category": "deduction", "sortOrder": 3 },
  { "label": "实发工资", "value": 4730, "category": "summary", "sortOrder": 4 }
]
```

金额按两位小数存储。空值项目可不展示；原表中明确填写 `0` 的项目允许展示。标签最长 50 字，单人工资项目最多 80 项。

## 4. 数据结构

### 4.1 `salary_import_profile` 项目字段映射

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK AUTO_INCREMENT | 主键 |
| company_id | BIGINT NOT NULL | 企业 ID |
| project_id | BIGINT NOT NULL | 项目 ID |
| header_signature | CHAR(64) NOT NULL | 规范化表头 SHA-256 |
| source_headers | JSON NOT NULL | 原始表头及顺序 |
| mapping_json | JSON NOT NULL | 列到字段/分类的映射 |
| status | TINYINT NOT NULL DEFAULT 1 | 1 有效，0 停用 |
| last_used_at | DATETIME NULL | 最近使用时间 |
| created_by | BIGINT NULL | 创建人 |
| created_at | DATETIME NOT NULL | 创建时间 |
| updated_at | DATETIME NOT NULL | 更新时间 |

索引：

- 唯一索引 `(company_id, project_id, header_signature)`。
- 普通索引 `(company_id, project_id, status)`。

### 4.2 `salary_detail` 扩展字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| item_snapshot | JSON NULL | 员工本月动态工资项目快照 |
| source_row_no | INT NULL | 原工资表行号 |

现有标准金额列继续保留，用于批次汇总、查询、导出和旧工资条兼容。

### 4.3 `salary_batch` 扩展字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| import_profile_id | BIGINT NULL | 本批次使用的字段映射 |
| source_sheet_name | VARCHAR(100) NULL | 原工作表名称 |

迁移必须幂等；历史数据保持 `NULL`，不回填、不改变现有金额。

## 5. 页面结构

### 5.1 Web 工资条导入

1. 选择项目和工资月份。
2. 拖拽或选择 XLSX/CSV。
3. 显示识别结果：工作表、表头行、员工数、工资项目数。
4. 必要时显示字段映射面板。
5. 显示逐行预览：员工匹配、应发、实发、动态项目和异常。
6. 无阻断错误后创建工资批次；金额核对差异仅提示，确认后允许按原表金额创建。

示例按钮提供“下载 XLSX 示例”和“下载 CSV 示例”，仅用于演示，不作为强制模板。

### 5.2 小程序员工工资条

- 顶部保持工资月份、项目、实发金额和签收状态。
- 中部按 `item_snapshot` 的原表顺序展示收入、扣款和汇总项目。
- 历史工资条没有快照时，继续使用现有固定字段展示。
- 底部保持异议、手写签名和签收流程。

## 6. 核心业务流程

1. 薪资专员选择授权项目和工资月份。
2. 浏览器读取 XLSX/CSV，检测工资明细工作表和表头。
3. 系统根据别名库和项目历史映射生成字段映射。
4. 关键字段无法确定时，薪资专员完成映射。
5. 系统生成标准金额和每人工资项目快照。
6. 后端按企业和项目范围匹配在职员工，校验重复行和金额。
7. Web 显示预览；员工无法匹配、重复、公式或非法金额等阻断错误禁止创建，金额关系异常仅提示并允许确认后继续。
8. 创建批次时事务写入批次、工资明细、动态快照和字段映射。
9. 发布后员工通过小程序查看原项目工资条并完成签名、签收或异议。

## 7. 接口设计

### 7.1 查询项目字段映射

`GET /api/payroll/import-profiles?projectId=16&headerSignature=<sha256>`

权限：`payroll:manage`，并校验账号项目数据范围。

响应：

```json
{
  "profileId": 8,
  "projectId": 16,
  "sourceHeaders": ["姓名", "夜班奖", "实发工资"],
  "mapping": [
    { "columnIndex": 0, "target": "employeeName" },
    { "columnIndex": 1, "target": "custom", "category": "income" },
    { "columnIndex": 2, "target": "netAmount", "category": "summary" }
  ]
}
```

### 7.2 工资表预校验

扩展现有 `POST /api/payroll/batches/preview`。

请求新增：`headerSignature`、`sourceHeaders`、`mapping`、`sheetName`，每行新增 `itemSnapshot` 和 `sourceRowNo`。

后端必须重新校验映射和快照，不能信任浏览器计算结果。

### 7.3 创建工资批次

扩展现有 `POST /api/payroll/batches`。

事务内：

- 再次校验企业、项目和员工归属。
- 写入或更新项目字段映射。
- 写入 `salary_batch.import_profile_id`。
- 写入 `salary_detail.item_snapshot` 和 `source_row_no`。
- 保持现有批次合计和操作日志。

### 7.4 员工工资条查询

扩展现有本人工资条接口，响应新增：

```json
{
  "items": [
    { "label": "夜班奖", "value": 380, "category": "income", "sortOrder": 2 }
  ]
}
```

只能返回登录员工本人的工资条；查看仍写入现有工资条证据日志。

## 8. 权限与风控

- 字段映射查询、保存和工资导入均校验 `company_id`、项目授权和 `payroll:manage`。
- 身份证号仅用于摘要匹配，不写入工资项目快照、日志或错误详情。
- 手机号、身份证号和银行卡号不得进入动态展示项目。
- 拒绝公式、负数金额、重复员工、跨项目员工和超限 JSON。
- 动态标签做 HTML 转义；导出时做 CSV/Excel 公式注入防护。
- 字段映射新增或变化写入操作日志，记录项目、表头签名和操作人，不记录员工敏感数据。
- 工资条查看、签名、签收、拒签和异议继续使用现有审计留痕。

## 9. 兼容与扩展

- 历史工资条 `item_snapshot=NULL` 时使用原固定字段渲染。
- 现有 CSV/XLSX 智能识别和固定金额字段继续有效。
- 不删除旧字段，不改变现有发放、撤回和签收接口语义。
- 后续可增加项目映射管理页、映射版本回退及工资异常规则，但不纳入本轮。

## 10. 测试与验收

- XLSX 单层表头、双层表头、前置标题、多工作表。
- 任意列顺序、历史别名、未知收入项、未知扣款项、文本展示项。
- 缺少身份列、缺少实发列、多候选关键列和映射复用。
- 姓名重名、跨项目员工、离职员工、重复员工和金额异常。
- 动态快照写入、本人接口隔离、历史固定工资条兼容。
- Web 预览和小程序展示字段名称、顺序、金额一致。
- 运行 `npm run lint`、`npm run check`、`npm run postcheck` 和 `npm audit --audit-level=high`。
