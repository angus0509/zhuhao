## 6. 上线中修复的问题

### 6.1 驻厂角色中文检查误判

- 原因：部署脚本 MySQL 标量查询未指定 UTF-8 客户端字符集。
- 修复：统一增加 `--default-character-set=utf8mb4`。
- 数据影响：无，生产角色数据原本正确。

### 6.2 汇总接口返回 HTTP 500

- 接口：`GET /api/summary`。
- 原因：驻厂迁移为员工表增加 `risk_level` 后，风险汇总 SQL 的 `risk_level` 未指定表别名，触发 MySQL `ER_NON_UNIQ_ERROR`。
- 修复：使用 `r.handle_status` 和 `r.risk_level` 明确引用风险告警表字段。
- 回归：通用 smoke 和驻厂 smoke 均通过。

### 6.3 员工详情接口返回 HTTP 500

- 接口：`GET /api/employees/:id`。
- 原因一：详情查询读取招聘人和供应商字段，但遗漏 `hr_recruiter`、`hr_recruitment_supplier` JOIN。
- 原因二：附件服务复用 `assertEmployeeScope` 做数据范围校验，但员工服务遗漏导出该函数。
- 修复：补齐招聘来源 JOIN，导出员工数据范围校验函数，并补充雇主险字段。
- 防回归：通用 smoke 会从员工列表读取首条员工并访问详情接口。
- 生产结果：`/api/employees/30` smoke 通过，最终部署后日志无新 API 错误。

## 7. 回滚依据

若灰度期间出现严重故障，按以下顺序处理：

1. 停止扩大灰度范围，保留当前日志和错误时间点。
2. 使用 `code-backup-20260805-111958.tar.gz` 恢复上线前代码。
3. 使用 `hr_roster-20260805-111958.sql.gz` 恢复数据库前，先对故障现场数据库再次完整备份。
4. 如涉及附件异常，使用 `attachments-20260805-111958.tar.gz` 恢复。
5. 重建应用容器并验证健康接口、登录、花名册和权限数据范围。

数据库恢复属于高风险操作，必须由授权人员确认恢复时间点后执行。
